One design gap I need to flag before the code

Looking at trainingStore.ts closely: markReviewedCorrectly deletes a mistake once it's answered right twice. That means there's currently no memory of what a learner overcame — only what's still wrong today. A "history" page built on that would only ever show unsolved problems, never growth. So I'm adding one small, additive piece of state — resolvedMistakes — that archives an item at the moment it graduates out of the active list, instead of just discarding it. Nothing breaks; it's a new persisted array alongside the existing one.

Here are all the pieces, in order.

Replace the existing markReviewedCorrectly with this version (same signature, now archives before deleting):

ts
markReviewedCorrectly: (word) => {
  set((state) => {
    const today = new Date().toISOString().slice(0, 10);
    const newlyResolved: ResolvedMistakeEntry[] = [];

    const updated = state.mistakes
      .map((m) =>
        m.word.toLowerCase() === word.toLowerCase()
          ? { ...m, reviewedCorrectly: m.reviewedCorrectly + 1 }
          : m,
      )
      .filter((m) => {
        const isTarget = m.word.toLowerCase() === word.toLowerCase();
        if (isTarget && m.reviewedCorrectly >= 2) {
          newlyResolved.push({ ...m, resolvedDate: today });
          return false; // graduated — drop from active list
        }
        return true;
      });

    return {
      mistakes: updated,
      resolvedMistakes:
        newlyResolved.length > 0
          ? [...state.resolvedMistakes, ...newlyResolved]
          : state.resolvedMistakes,
    };
  });
},

Where this leaves the Supabase side, for Antigravity

Everything above is pure Zustand + localStorage, so it'll work immediately with zero backend changes. When Antigravity wires the Supabase sync, the shape it needs to persist is exactly the two arrays in trainingStore:

mistakes: MistakeEntry[] → { word, correctAnswer, wrongAnswer, exerciseType, date, reviewedCorrectly }
resolvedMistakes: ResolvedMistakeEntry[] → same fields + resolvedDate

A user_id-keyed table with those columns, upserted the same way syncUserStats already does for user_stats, is all it needs — no schema surprises.

Two honest caveats worth knowing before you ship this: wrongAnswer is currently always saved as an empty string (ExerciseCard never passes the learner's actual wrong answer up to ExerciseEngine), so the history can show what was right, not what they typed — fixable later if you want that detail. And since resolvedMistakes starts empty for everyone, existing users won't see any "Mastered" history until they clear a mistake going forward — there's no way to retroactively recover what's already been deleted.
